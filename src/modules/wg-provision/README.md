# Модуль wg-provision

Установка агента на новый VPS из интерфейса: `POST /api/v1/wg/nodes/{id}/provision`
(право `wg:node:provision[:own]` — с областью «свои» только на свою ноду) с
хостом, SSH-ключом или паролем.

Постановка (`WgProvisionService`):

- создаётся одноразовый токен регистрации с меткой ноды (час): агент привяжется к
  ней при регистрации;
- SSH-ключ/пароль и токен шифруются `WgSecretBox` и только в таком виде попадают в
  данные задачи `wg.provision-node` (`track`, дедупликация `wg-provision:<nodeId>` —
  повторная установка параллельно не запускается; не поставлена — токен отзывается);
- нода переводится в `provisioning`; ответ — `202 { jobId }`, прогресс — комната `job`
  по сокету и `GET /api/v1/jobs/{id}`.

Задача (`WgProvisionNodeJob`, воркер): по SSH (ssh2, при пользователе не-root — `sudo
-n`) создаёт свой рабочий каталог (`mktemp -d /tmp/wg-admin.XXXXXXXX`, 0700),
загружает в него токен файлом (umask 077) и выполняет план (`provision-plan.ts`):

1. снимает службу `wg-admin-agent` (агент без воркеров, который сам держал
   интерфейсы), если она есть: два агента на одних интерфейсах мешали бы друг другу;
2. выполняет команду установки — ту же, что выдаёт `POST /wg/nodes/{id}/install-command`
   (`WgNodeAgentService.commandFor`), но с `--token-file`: токен не попадает в
   аргументы команд. `install.sh` с бэкенда ставит агента службой `agent-wg`, воркеры
   wg и socks с сервера, пакеты и параметры ядра.

Каталог удаляется после запуска и при сбое. Провал — токен отозван, нода в `error`;
успех подтверждает сам агент: регистрация привязывает его к ноде, выход на связь —
`online`. Адрес бэкенда — из запроса или `AGENT_PUBLIC_URL`/`APP_PUBLIC_URL`; агенту он
нужен доступным с VPS.

Задача ставится со `scope: wg-node/<nodeId>`: её обновления приходят в
сокет-комнату ноды, видят её все с правом просмотра ноды, отменяют — с правом
установки (`WgNodeJobAccessPolicy`; с областью `own` — только задачи своих нод). `WgProvisionListener` на
`JobUpdatedEvent`: провал или отмена установки (в том числе закрытая reaper
после падения воркера) переводят ноду из `provisioning` в `error`.

Удаление агента — `POST /api/v1/wg/nodes/{id}/uninstall` (право
`wg:node:provision[:own]`, SSH как при установке) → задача `wg.uninstall-node`:
`/opt/agent-wg/bin/agent uninstall --instance wg --purge` — агент вызывает у воркеров
`POST /cleanup` (wg снимает свои интерфейсы, туннели и цепочки `WG_ADMIN_*`, socks
закрывает прокси), удаляет службу, программу, настройки, данные и пакеты, поставленные
установкой; другие экземпляры агента на узле не затрагиваются. Успех — агент отозван и
удалён, нода снова `created`.

Вывод установщика идёт в лог задачи построчно по ходу выполнения
(`SshRunner.exec` с `onLine`), со временем от начала каждой строки.
