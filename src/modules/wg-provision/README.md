# Модуль wg-provision

Установка агента на новый VPS из интерфейса: `POST /api/v1/wg/nodes/{id}/provision`
(право `wg:node:provision`) с хостом, SSH-ключом или паролем.

Постановка (`WgProvisionService`):

- перевыпускается ключ агента ноды (старый отзывается);
- SSH-ключ/пароль и ключ агента шифруются `WgSecretBox` и только в таком
  виде попадают в данные задачи `wg.provision-node` (`track`, дедупликация
  `wg-provision:<nodeId>` — повторная установка параллельно не запускается);
- нода переводится в `provisioning`; ответ — `202 { jobId }`, прогресс —
  комната `job` по сокету и `GET /api/v1/jobs/{id}`.

Задача (`WgProvisionNodeJob`, воркер): по SSH (ssh2, при пользователе
не-root — `sudo -n`) загружает установщик (`install-script.ts`, тот же, что
`GET /api/v1/wg-agent/install.sh`) в `/tmp/wg-admin-install.sh` и выполняет
его с ключом агента (передаётся base64 — экранирование не нужно). Установщик
ставит зависимости, скачивает бинарь агента с бэкенда по ключу, сверяет sha256
и запускает службу systemd. Провал — нода в
`error`; успех подтверждает сам агент, выйдя на связь (нода станет `online`).
Адрес бэкенда — из запроса или `APP_PUBLIC_URL`; агенту он нужен доступным
с VPS.

Установка вручную — та же команда на VPS (её возвращают создание ноды и
ротация ключа, поле `installCommand`).

Задача ставится со `scope: wg-node/<nodeId>`: её обновления приходят в
сокет-комнату ноды, видят её все с `wg:node:view`, отменяют — с
`wg:node:provision` (`WgNodeJobAccessPolicy`). `WgProvisionListener` на
`JobUpdatedEvent`: провал или отмена установки (в том числе закрытая reaper
после падения воркера) переводят ноду из `provisioning` в `error`.

Удаление агента — `POST /api/v1/wg/nodes/{id}/uninstall` (право
`wg:node:provision`, SSH как при установке) → задача `wg.uninstall-node`:
установщик с `--uninstall` — остановка службы (агент по SIGTERM откатывает
свои интерфейсы, туннели и пробросы), страховочный `cleanup`, откат хоста по
журналу установки (пакеты, forwarding, модули — см. `agent/README.md`),
удаление бинаря, unit и `/etc/wg-admin`. Успех — ключ
отозван, нода снова `created`.

Вывод установщика идёт в лог задачи построчно по ходу выполнения
(`SshRunner.exec` с `onLine`), со временем от начала каждой строки.
